# Архитектура Veyl

## Стек и данные

Vue 3 + TypeScript + Vite + Pinia + Vue Router. Fastify + встроенный в Node 24 SQLite + Zod. SSE передаёт уведомления об изменениях, HTTP API - проверенные данные. Нет WebGL, видеофона, библиотек анимаций или обязательного CDN.

SQLite хранит настройки сайта с номером ревизии, проекты, статусы, расписание, диалоги, сообщения, хеш пароля, хеши сессий и журнал действий. Содержание сайта пока хранится одним проверяемым JSON-документом: это упрощает небольшой личный сайт, а оптимистическая ревизия предотвращает потерю изменений из другой вкладки. Перенос в PostgreSQL возможен при росте нагрузки, но для одного владельца сейчас не нужен.

## Карта компонентов

Публичный маршрут HomeView: HeroSection → направления → SkillsSection → CasesSection → ProjectsSection → SystemsSection → контакты. ChatPanel загружается при открытии. DisplayControls и StatusBadge общие для сайта и панели.

AdminView сначала проверяет серверную сессию. После входа открывает обзор, AdminChatPanel, AdminStatusEditor, AdminProjectEditor, AdminSiteEditor и AdminSettings. Проверка доступа выполняется также на каждом серверном endpoint; скрытие интерфейса не считается защитой.

Site store отвечает за запросы, последовательное сохранение с ревизией, публичные и закрытые SSE-подписки. localStorage содержит только язык, тему и качество эффектов. Сообщения и доступ не хранятся в браузерном демо.

## Границы доступа

Публичный API исключает скрытые, приватные и черновые проекты, расписание и быстрые ответы. Посетитель получает только собственную переписку и публичные поля своей сессии. Заметки, архив и другие поля управления не выдаются ему. Идентификатор диалога сервер берёт из HttpOnly-cookie, а не из присланного посетителем JSON. Отправителя сообщения также задаёт сервер.

Пароль проверяется через scrypt и безопасное сравнение. Cookie владельца живёт 8 часов, посетителя - 90 дней. В production включён Secure; сайт требует HTTPS. Все изменения проверяют точный PUBLIC_ORIGIN. Вход и сообщения ограничены по частоте. Смена пароля и выход отзывают сессии и их SSE-подписки.

Загружаемые обложки ограничены 1.4 MB, PNG/JPEG/WebP и проверкой сигнатуры. SVG и произвольные пути не принимаются. Для массового публичного сервиса понадобятся отдельное хранилище, полноценное декодирование изображений и дополнительные меры против распределённого спама.

## Статусы

Временный статус с будущей датой перекрывает расписание. После окончания сервер сохраняет базовый статус возврата и очищает дату. Затем действует первое подходящее правило расписания по Europe/Moscow либо базовый статус. Проверка идёт на сервере; закрытие вкладки её не останавливает. В интерфейсе отдельно хранится текущий вычисленный статус, чтобы расписание не перезаписывало выбранную базу.

## Изображения и анимации

Использованы предоставленные аватар, баннер и прозрачная эмблема. WebP: эмблема около124 KB, баннер370 KB и аватар47 KB. Баннер ниже первого экрана загружается лениво. Manrope хранится локально с кириллицей и лицензией.

CSS создаёт частицы, кольца, плавающие элементы, кубы и движение связей. JS реагирует на указатель и прокрутку одним запланированным кадром; постоянного render loop нет. IntersectionObserver управляет появлением блоков и паузой вне экрана. Скрытая вкладка останавливает CSS-анимации. Light отключает непрерывные эффекты, системный reduced-motion имеет приоритет. На телефонах используется отдельная компоновка и меньше частиц.

Исходный видео-референс из старого чата не был доступен в этом сеансе. Существующие GIF/MP4 не подменяют его; тяжёлые GIF не включены в сайт.

## Публикация и проверка

Исходники опубликованы в veylcode/veyl-site. Серверные секреты и пользовательские данные исключены из Git и Docker build context. Локальные проверки выполняют тесты и TypeScript/production build; включение CI ожидает отдельного разрешения workflow. Для внешнего доступа нужны выбранный хостинг, HTTPS-домен и постоянный диск.

Автоматические тесты проверяют серверные границы, а браузерные проверки - реальные формы, обновления, тему, язык и адаптивность. Размер сборки не доказывает FPS на слабом устройстве. Физические слабые ПК, Safari и Firefox ещё требуют отдельной проверки.
